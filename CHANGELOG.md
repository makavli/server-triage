# Changelog

## 1.1.2 (2026-11-20)

- Copy: a command that still holds a blank you have not filled names it in the toast ("Copied with HOST still to fill"), and a held Enter copies once.
- Setup: a refused value says "(not valid)" beside its name, not only in colour, and goes back to the last good one when you leave the field. A file or a data directory cannot be `/`, `/.` or `.`, or climb out with `..`. Pins and notes for entries that changed since (a new command gets a new link) are listed under Your data, with the note's text, and can be deleted (if the list changes before your second click, it asks again). A line under Export says the file holds your values and notes. The toast now shows over the open panel, and Import shows the keyboard focus.
- Import takes a file up to 64 MB, so any export fits, and a file too big or unreadable says so. The question shows each note whole and names the filters the file brings, a long run of empty lines is counted as a long run of blanks is, and what the file holds that cannot be kept (hidden characters, a wrong shape) is counted there and in the toast. An imported command loses a trailing newline, which would run it on paste. A note or a meaning with hidden characters is left out, as a command already was, and typing drops them. The import compares with what is stored now, even if another tab just changed it.
- Your entries: a draft survives one Escape (a second drops it) and a second Add an entry, and an empty command says so. A note you are writing in the pinned list, and the Setup field you are typing in, survive another tab's save. A save the browser refuses says so, the work it holds only in memory is no longer replaced when another tab saves, and the page recovers when saving works again, or when a database that failed to open opens next time. At most 1000 of your entries load, whatever the database holds. Delete my data reads as before once it has acted.
- Search counts a pinned entry once. A link to an entry your filters hide says so without clearing your search, and a link to a part of the page that is not on the sheet changes nothing. Unpinning from the pinned list keeps the focus on the page.
- The sheet, 39 corrections. Heavy commands say so (`conntrack -L` on a full table, `find` over `/`, `_cat/shards`, `pgstatindex`, `explain("executionStats")`, CPU and goroutine profiles), and so does output that may hold secrets (crontabs, Redis ACL hashes, statements logged with their literals). `mysqldump --source-data` takes a brief global read lock and `mariadb-dump --master-data` takes none (both checked on the server). VACUUM's final truncation and `VACUUM (TRUNCATE false)` are explained. `binlog_expire_logs_seconds` is tagged as able to lose data, and `mongodump` and the netrc writer as changing state. `patronictl pause` and `resume` get their own entries, and single-user `postgres --single` gets one, tagged as able to lose data. The `TRUNCATE` checkpoint sets `.timeout 5000`. Facts fixed: MariaDB's `thread_cache_size` default (256), what `haproxy -c` prints, what an empty EndpointSlice list means, the kubelet's `nodefs.inodesFree`, Go's `SSL_CERT_DIR`, `proxy_http_version 1.1` for WebSockets, the two `arping` flavours, NFSv3 locking, what `certbot --dry-run` runs, undoing a Kafka offset reset per partition, and the HAProxy socket's `level admin`.
- The build checks that a section's id has a shape the page can keep a pin or a note for, and the tests count one entry per code block in the sheet.

## 1.1.1 (2026-11-20)

- Delete my data, and deleting one of your entries, now need a real second click: a double-click, a quick second click or a held Enter no longer deletes.
- A value in Setup takes letters, digits and `. _ : / @ + = , % -` (a port or a process ID, digits only), and cannot start with `-` or hold `--`, so a command you copy never gets a quote, a `;`, a `$(...)` or an extra option from it. A value that does not fit is marked and the last good one holds; a file or a stored value that does not fit is dropped.
- An import asks one question that lists everything the file changes: the entries it adds or replaces, each with its whole code (what does not fit in the question is named, never cut short), the notes, the pins, the values and the filters. A file with nothing new says so.
- A database that fails to load (or loads slowly) is no longer overwritten by the next change to your values or filters.
- The characters refused as hidden now include every unusual space (no-break and the like), soft hyphens, variation selectors and the other invisible ones. The build, the page and the repository checks share one list.
- A search no longer breaks on text holding a letter whose lower case is longer, such as the Turkish İ.
- The sheet: `sh.stopBalancer()` and `sh.startBalancer()`, `pg_wal_replay_pause()` and `pg_wal_replay_resume()`, and the two `REPLICAOF` commands each get their own entry, so one copy no longer undoes itself or hits two nodes, and the build now fails on such a pair. `CLIENT KILL id ID` fills only the id (the build checks for a keyword spelled like a blank). py-spy says that it pauses the process unless you add `--nonblocking`, `CONFIG GET tls-*` warns that key passphrases print in clear, and `stop-writes-on-bgsave-error no` is tagged as able to lose data. Links to the entries that were split now land on their section.

## 1.1.0 (2026-11-20)

- The sheet grows from 12 sections to 20, 1329 entries in all. New: storage and filesystems, AWS, Google Cloud and Azure, the JVM, Node.js, Python and Go runtimes, Kafka and RabbitMQ, SQL Server, SQLite, MongoDB, and Elasticsearch and OpenSearch. PostgreSQL, MySQL and MariaDB, and Redis go much deeper (replication, locks, vacuum, memory, slow queries), and so do the host, network and Kubernetes sections. The commands and error texts were run in containers on the versions the sheet's intro names; the cloud CLIs were checked for syntax only, and the few errors that could not be triggered come from each project's own docs or source.
- Tags: a command that changes state says **Changes state**, one that can lose data says **Can lose data**, and a command for one distribution or from one version on says so (Debian and Ubuntu, RHEL family, PostgreSQL 16+).
- Setup: type your values once (host, pod, database...) and every command shows and copies them. Filters hide what changes state, keep one distribution, or hide what needs a newer version than yours.
- Pins and notes on any entry, gathered at the top; your own entries, searchable with the rest. They stay in this browser's local database, and Export and Import move them between devices as a JSON file.
- Search knows synonyms (`oom` finds "out of memory"), highlights the matches, and the arrow keys or `j` and `k` walk the results.
- Every entry has its own link, which opens the sheet on it; an old link to an entry that changed falls back to its section.

## 1.0.0 (2026-11-20)

- First release. The sheet has 12 sections: the triage loop, the first minute on a host, an error decoder, services and logs, resources, DNS and the network path, TLS, HTTP and proxies, containers and Kubernetes, PostgreSQL, MySQL and Redis.
- The app is one page built from `CHEATSHEET.md`. It has search (every word must match), click or Enter to copy, and a request path that links each hop to its section. It follows the light and dark system theme.
- It installs as an app from Edge or Chrome and works offline. `index.html` also opens from disk with no server. It makes no requests beyond its own files.
